# conventions

## Skills

16 skills, one directory each at `skills/<name>/SKILL.md`:
`wiki`, `save`, `wiki-ingest`, `wiki-query`, `wiki-lint` (core);
`autoresearch`, `canvas`, `defuddle`, `wiki-fold`, `wiki-mode`, `wiki-retrieve`,
`wiki-cli`, `youtube` (extensions, `youtube` fork-only - `mem:fork_local`);
`obsidian-markdown`, `obsidian-bases`, `think` (reference).

- Frontmatter is the portable Agent Skills subset: exactly `name` and
  `description`, nothing else. No mirrored `commands/` files; Claude invokes
  plugin skills as `/claude-obsidian:<name>`.
- A skill body must resolve `$PRODUCT_ROOT` explicitly and must never resolve a
  product helper from a user-vault cwd (`_validate_skill_helper_paths`).
- Any `../wiki/references/` link must state that it resolves relative to the
  skill's own directory, not the vault (`_validate_wiki_reference_link_anchors`).
- Agents at `agents/<name>.md` need a `tools:` key. `verifier.md` is read-only by
  design (Read, Grep, Glob, Bash); never grant it Edit/Write.

## Capability contract

Every skill needs a matching `config/capabilities.json` entry, and the two sets
must be exactly equal: `tests/test_contracts.py` asserts set equality and the
literal count 16. Each entry declares `tier`, `implementation_paths`,
`read_scope`, `write_scope`, `needs`, `transaction_type`, `confirmation`
(`mutation` / `network_egress` / `destructive`), and `verification_command`.
The verifier must be behavioral; an empty one requires an explicit
`verification_reason`. `needs.network` and `confirmation.network_egress` must
agree, so a skill that gains any egress path must update both. Adding a skill
therefore touches `skills/`, `config/capabilities.json`, and the count
assertions in `tests/test_contracts.py` and `tests/test_setup_multi_agent.py`.

## Version authority

`.claude-plugin/plugin.json` is the sole version authority. `config/public-marketplace.json`
must carry the same top-level `version`, exactly one plugin entry, `source: "./"`,
and no per-entry `version`. Keep the fork's `pyproject.toml`/`uv.lock` version in
step by hand (`mem:fork_local`).

## Other invariants

- No top-level `bin/`; claude.ai rejects a plugin that ships one.
- `.vault-meta/` is ignored runtime state (locks, journals, indexes, caches,
  `mode.json`, `transport.json`). Never assume a transport or mode; read the
  state file.
- `RELEASE_MANIFEST.json` and `SHA256SUMS` are generated by a release build. The
  repo-root copies are the maintainer's snapshot of the last public release.
- Wiki page structure, frontmatter, and wikilinks are governed by the
  `obsidian-markdown` skill, not by this memory.
